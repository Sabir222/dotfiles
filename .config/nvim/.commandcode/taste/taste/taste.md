# Taste
- Prefers a clean, lean config: deletes dead/dormant files outright (e.g., an unused init rewrite, an orphaned lazyvim.json, a stale draft containing a postgres DSN, and fully commented-out plugin files) rather than keeping or migrating them. Confidence: 0.9
- Keeps configuration self-consistent — removes references to things that aren't actually installed (e.g., pruning themes with no installed plugin from the theme switcher). Confidence: 0.7
- Performance-conscious about the Neovim config: monitors startup time and wants it fast (asked whether ~103ms startup stats are good). Confidence: 0.6
- Treats kickstart.nvim as the reference baseline for the config and trusts the kickstart devs' decisions; wants to know how upstream has evolved before deciding on changes, and after a migration/fix asks for a full parity check of what is still implemented differently before considering the work done. Confidence: 0.8
- Communicates in terse, imperative fragments ("no remove X, fix Y, delete Z", "ok now lets address a error...") and expects direct execution without lengthy preamble or confirmation. Confidence: 0.9
- Reports bugs by pasting the raw error/stack trace verbatim with minimal context ("could be other files too idk", "i get this error investigate why and fix") and expects the agent to diagnose and fix the root cause itself, without being walked through clarifying questions. Confidence: 0.8
- Explicitly separates discussion-only phases from modification phases ("dont do modification just discussion now") — wants analysis/comparison delivered as discussion before any edits are made. Confidence: 0.7
- Prefers lazy-loading plugin management (keeps lazy.nvim) because the config has many plugins; not interested in adopting minimal/eager-loading managers like vim.pack. Confidence: 0.8
- Wants the config to follow the officially recommended patterns/APIs for their installed Neovim version — asked whether their LSP config was "the recommended config for 0.12", then immediately approved applying all three recommended 0.12 deltas (mason-lspconfig automatic_enable, lua_ls on_init, diagnostic config); later directed adopting `vim.hl.on_yank()` and dropping the redundant `showmode` for 0.12 currency, while accepting staying on the classic treesitter API since the new `install()` isn't in the installed version. Confidence: 0.9
- Keeps Neovim itself on the latest stable release, upgrading promptly (switched from 0.11.5 to 0.12.4) to get full benefit of recently added APIs/features. Confidence: 0.6
- Open to migrating mature, working setups toward the ecosystem's current direction — proactively raised moving from nvim-cmp to blink.cmp and from nvim-treesitter's config module to the native 0.12 treesitter API, even though the existing config is deeply tuned, and confirmed the full swap without hesitation once the tradeoffs were laid out; later inquired about adopting the bleeding-edge `require('nvim-treesitter').install()` API and then directed the actual adoption (tracking nvim-treesitter on the `main` branch) even after being advised to stay on stable, showing continued appetite for current APIs. Confidence: 0.9
- For experimental plugin/tool swaps, keeps the replaced option around rather than deleting it (explicitly asked to only comment out vim-sleuth, not remove it) and wants the change annotated as a test with a comment spelling out the revert path ("this is a test; if you don't like it, use tpope/vim-sleuth"). Confidence: 0.9
- Wants completed, verified work to end in a git commit and push to their GitHub dotfiles repo ("if all good remove the kickstart dir and push to github") — proceeds to cleanup/commit only after confirming the config loads cleanly, and expects agent artifacts (e.g. `.commandcode/`) to be excluded from commits. Confidence: 0.7
